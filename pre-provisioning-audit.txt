2. FILE SYSTEM PERMISSIONS (CRITICAL FINDINGS)
Status: NON-COMPLIANT

2.1: World-Writable Root Directory
  - Path: /opt/kijanikiosk/
  - Current Mode: 777 (drwxrwxrwx)
  - Risk: HIGH. Any user on the system can create, delete, or modify files
    in the application root. This allows for symlink attacks and binary
    replacement.
  - Required: 755 (drwxr-xr-x) or stricter.

2.2: World-Writable Config Directory
  - Path: /opt/kijanikiosk/config/
  - Current Mode: 777 (drwxrwxrwx) [Inferred from context of dirty state]
  - Owner: root:kijanikiosk
  - Risk: CRITICAL. Although owned by root, the 'other' write bit allows
    ANY user to modify configuration files (e.g., db.env). This leads to
    immediate privilege escalation or data exfiltration.
  - Required: 750 (drwxr-x---) for directory, 640 (-rw-r-----) for files.

2.3: World-Writable Scripts & Shared Directories
  - Paths: /opt/kijanikiosk/scripts/, /opt/kijanikiosk/shared/
  - Current Mode: 777 (drwxrwxrwx)
  - Risk: HIGH. Scripts directory being world-writable allows code injection.
    Shared directory lacks SGID bit enforcement in the parent (though child
    /logs has it).
  - Required: 750 or 770 with SGID (2770) for shared logs only.

2.4: ACL Configuration on Config
  - Path: /opt/kijanikiosk/config/
  - Current Mask: r-x
  - Default Mask: r-x
  - Issue: The default mask (r-x) allows Execute permissions on new files.
    Config files should be data (no execute). The umask override is not
    strictly enforcing 640 (read-only group) if the creator requests execute.
  - Required: Default Mask should be r-- to enforce 640.
